# Elysia's notes, round 5: build prompts

Her words are quoted; each item is followed by the build prompt and what we added on top.

## 1. Build any class type and offer herself (**High**)
> "when i add a new class type i can only choose for it to be paid for with existing packages (mat or reformer)… I want to be able to build it."

**Prompt:**
- **Settings → Packages → "+ Add":** choose a **Package** or a **Single class**.
  - **Single class:** Trial or Drop-in, a name she writes ("Pre and Post Natal Reformer Trial"), what it's for, price, short description.
  - **Package:** what it's for, classes per week, months, price, short description (as now).
- **"For"** lists every class type that has its own packages (Reformer, Mat, …) plus **"+ New class type"**. That opens a short form right there:
  - name, spots, minutes, classes used, default location, description;
  - it's saved straight away, chosen in "For", and appears under Class types too.
- **Class types:** edit spots, minutes, classes used, location and description; turn active on or off; **Delete**.
- **Packages and single classes:** on sale or not; **Delete**.
- **Clients:** Packages shows one tab per class type that has something on sale (Reformer / Mat / Pre & Post Natal / Private…). Each tab shows its packages, then its trials and drop-ins.
- **Our additions:**
  - Delete never breaks history: something already used by a payment or a class is removed from her lists, but past receipts and classes keep it. Deleting a class type with classes still to come is refused, with the reason.
  - Every label that said "Reformer"/"Mat" now reads the class type's own name: package names, My classes, receipts, stats, the client page, the "this package is for … classes only" notice, and Every week.

## 2. Codes for trials, drop-ins, packages and events (**High**)
> "give me an option to tick what it applies to: trial, drop in, package, event."

**Prompt:**
- Under the code name, four ticks: **Trial · Drop-in · Package · Event** (Package ticked by default). Rewards on a client's page have the same ticks.
- On a class or event page, the client gets a "Have a code?" link before reserving. Their reward is applied by itself.
- Free classes only make sense on a package, so that option asks for Package only.
- Her answer: a code and the student discount don't add up; the bigger one applies.

## 3. Notifications to the studio (**High**)
> "send me notifications everytime someone joins a class (because what if someone joins a 7 am class that was empty and i dont go)…"

**Prompt:**
- An email to the studio for each of these:
  - a booking (marked **first booking** when the class was empty);
  - a new sign-up;
  - a cancellation;
  - a package request;
  - updated details;
  - an event booking.
- Studio-made changes don't email her.
- Settings → Booking rules → **Studio emails:**
  - the address they go to (defaults to the studio's contact email);
  - one switch per kind, all on.
- **Health answers are never put in an email**: "updated their details" only.
